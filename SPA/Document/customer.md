# คู่มือการใช้งาน SPA 49 — Customer Guide Storyboard

> เอกสารส่งต่อ Graphic Designer สำหรับจัดทำคู่มือลูกค้า
>
> ภาษา: ไทยเป็นหลัก โดยคงชื่อปุ่มตามหน้าจอจริง  
> ช่องทางหลัก: Mobile Web / LINE LIFF  
> เวอร์ชันอ้างอิง: Customer Web ปัจจุบัน (Booking 5 ขั้น)  
> วันที่ตรวจสอบเนื้อหา: 9 ตุลาคม 2026

## 1. วัตถุประสงค์และกลุ่มผู้อ่าน

คู่มือนี้ช่วยให้ลูกค้า SPA 49 สามารถ:

1. เลือกบริการและส่งคำขอจองสำหรับผู้รับบริการ 1–2 ท่าน
2. ติดตามสถานะผ่าน Secure Status Link หรือบัญชี LINE ที่เชื่อมไว้
3. ดูรายการจองและชำระเงินหลังรับบริการ
4. แก้ปัญหาเบื้องต้นโดยไม่ทำรายการซ้ำ
5. ลงทะเบียนรับคูปองจาก LINE Campaign ในกรณีที่มีแคมเปญเปิดใช้งาน

คู่มือนี้ต้องสื่ออย่างชัดเจนว่า การส่งคำขอสำเร็จยังไม่เท่ากับการยืนยันการจอง และการออกจากแอปธนาคารหรือเห็นหน้ากลับมายังเว็บไซต์ยังไม่ใช่หลักฐานว่าชำระเงินสำเร็จ ต้องรอผลยืนยันจากระบบเสมอ

## 2. แนวทางงานออกแบบ

### 2.1 รูปแบบแนะนำ

- ออกแบบแบบ Mobile-first โดยใช้สัดส่วนหน้าจอ `390 × 844 px` เป็นภาพหลัก
- ตรวจความอ่านง่ายเพิ่มเติมที่ความกว้าง `360 px` และ `430 px`
- หนึ่งหน้าคู่มือควรมีภารกิจหลักเพียงเรื่องเดียว ยกเว้นหน้าที่ระบุว่าเป็นภาพต่อเนื่อง
- ใช้ภาพ Screenshot จริงเป็น Hero ของแต่ละหน้า แล้ววางหมายเลข Callout รอบภาพ
- ใช้ข้อความสั้น กระชับ และเว้นพื้นที่หายใจ ไม่วางคำอธิบายทับข้อมูลสำคัญบนหน้าจอ
- ปุ่มหรือข้อความจาก UI ให้คงตัวสะกดตามที่ระบุในเครื่องหมายอัญประกาศ เช่น “ดำเนินการต่อ”

### 2.2 Visual direction

- Mood: Relaxing, Premium Organic, Authentic Thai Spa, Healing และ Serene
- สีหลัก: Forest Green `#4E6148`
- สีเน้น: Spa Gold `#C3A36C`
- พื้นหลัง: Warm Cream `#F7F4EB`
- พื้นผิวการ์ด: `#FCFAF5`
- สีข้อความหลัก: Deep Bark `#3A3F38`
- Heading: ฟอนต์ไทยแนว `Pridi` หรือ `Sarabun`; Body/UI: `Prompt`
- ใช้กรอบโค้งมน เส้นสีทองบาง และลายพฤกษศาสตร์อย่างพอดี โดยไม่บดบัง Screenshot
- สีสถานะต้องมีข้อความกำกับเสมอ ห้ามใช้สีเพียงอย่างเดียวในการสื่อความหมาย
- ตรวจ Contrast ของตัวอักษรขนาดเล็กให้ผ่าน WCAG 2.2 AA ก่อนส่งผลิต

### 2.3 กติกาสำหรับ Screenshot

- Capture จาก Test environment เท่านั้น ห้ามใช้ข้อมูลลูกค้าจริง
- ใช้ข้อมูลตัวอย่างที่ระบุในหัวข้อ 3 เพื่อให้ทุกหน้าต่อเนื่องกัน
- ปิดบังหรือแทนค่าหมายเลขโทรศัพท์, Booking ID, ข้อมูลสุขภาพ, Payment reference, QR และ Coupon code ก่อนส่งไฟล์ให้บุคคลภายนอก
- ห้ามใช้ QR ชำระเงินจริงใน Artwork ให้ใช้ Placeholder ที่สแกนไม่ได้และติดป้าย “ตัวอย่าง”
- ห้ามแสดง URL ที่มี Secure Status token หรือข้อมูลยืนยันตัวตนของ LINE
- หากต้อง Capture สถานะ Error ให้สร้างจาก Test fixture ห้ามรบกวนรายการจริง

## 3. ชุดข้อมูลตัวอย่างสำหรับงานกราฟิก

ใช้ข้อมูลสมมติชุดเดียวกันทุกหน้า เพื่อให้เรื่องราวต่อเนื่อง:

| รายการ | ข้อมูลตัวอย่าง |
| --- | --- |
| ชื่อผู้ติดต่อ | คุณมณี ใจดี |
| เบอร์โทรศัพท์ | `08X-XXX-1234` |
| ผู้รับบริการ 1 | มณี |
| ผู้รับบริการ 2 | พลอย |
| Booking ID | `BK-DEMO-001` |
| วันที่ | เลือกวันที่อนาคตจาก Test environment |
| เวลา | ใช้ Slot ที่ระบบ Test แสดงว่าว่าง |
| ข้อมูลสุขภาพ | ใช้ข้อความ “ข้อมูลตัวอย่างสำหรับงานออกแบบ” หรือปิดบังทั้งบรรทัด |
| Coupon code | `DEMO-XXXX` และทำลายน้ำ “ตัวอย่าง” |
| Payment QR | Placeholder ที่สแกนไม่ได้ |

ราคาบริการ, ระยะเวลา, วันว่าง, วิธีชำระเงิน และยอด Campaign ให้ใช้ค่าที่ระบบ Test แสดงในวันที่ Capture ไม่พิมพ์ค่าขึ้นใหม่จากความจำ

### หน้า 02 — เตรียมตัวก่อนเริ่ม

**เป้าหมาย**  
ทำให้ลูกค้าทราบว่าต้องเตรียมอะไรและเข้าใช้งานได้จากช่องทางใด

**ข้อความหลัก**

- หัวเรื่อง: “ก่อนเริ่มจอง”
- เตรียมโทรศัพท์ที่เชื่อมต่ออินเทอร์เน็ต
- เตรียมเบอร์โทรศัพท์ของผู้ติดต่อหลัก
- เตรียมชื่อเล่นและข้อมูลสุขภาพของผู้รับบริการแต่ละท่าน
- หากเปิดจาก LINE ระบบจะเชื่อมบัญชีเพื่อส่งข่าวสารสถานะการจอง
- หากเปิดจากเว็บไซต์ สามารถจองแบบ Guest และเชื่อม LINE ภายหลังได้

**ขั้นตอนลูกค้า**

1. เปิดเมนูจองบริการจาก LINE Rich Menu หรือลิงก์ของ SPA 49
2. หากระบบขอให้ยืนยันตัวตนกับ LINE ให้ทำตามหน้าจอ
3. แตะ `TH` หรือ `EN` ที่มุมบนเพื่อเลือกภาษา

**ภาพที่ต้องใช้**

- `[SCREENSHOT 02A]` หน้าแรกที่เห็น Logo และปุ่ม `TH / EN`
- `[SCREENSHOT 02B]` ตัวอย่างการเปิดผ่าน LINE LIFF โดยไม่แสดง LINE User ID

**Callout**

1. ตำแหน่งปุ่ม `TH / EN` — “เปลี่ยนภาษาได้จากมุมบนของหน้าจอ”
2. พื้นที่ Logo — “ตรวจสอบว่าเป็นหน้า SPA 49 ก่อนกรอกข้อมูล”

**คำเตือน / Privacy**

- ไม่ขอให้ลูกค้าส่งรหัสผ่าน LINE, OTP หรือข้อมูลธนาคารให้พนักงาน

### หน้า 03 — ขั้นตอน 1 จาก 5: เลือกบริการ

**เป้าหมาย**  
อธิบายการเลือกประเภทบริการ ระยะเวลา และตรวจสอบยอดโดยประมาณ

**ข้อความหลัก**

- หัวเรื่อง: “1. เลือกบริการที่ต้องการ”
- เลือกหมวด `แพ็กเกจพิเศษ`, `นวดและสปา` หรือ `บริการจองเดี่ยว`
- ในการ์ดบริการ ให้แตะตัวเลือกระยะเวลาและราคาที่ต้องการ
- เมื่อเลือกสำเร็จ ปุ่มจะแสดงคำว่า `เพิ่มแล้ว` พร้อมเครื่องหมายถูก
- เลือกได้สูงสุด 3 บริการต่อผู้รับบริการหนึ่งท่าน

**ขั้นตอนลูกค้า**

1. เลือกหมวดบริการ
2. อ่านชื่อ รายละเอียด ระยะเวลา และราคา
3. แตะ `+ เพิ่ม` บนตัวเลือกที่ต้องการ
4. ตรวจจำนวนบริการ ระยะเวลารวม และ `ราคาประเมินรวม` ที่แถบด้านล่าง
5. แตะ `ดำเนินการต่อ`

**ภาพที่ต้องใช้**

- `[SCREENSHOT 03]` หน้า Treatment Menu หลังเลือกบริการอย่างน้อยหนึ่งรายการ

**Callout**

1. Tab หมวดบริการ — “เลือกหมวดบริการ”
2. ปุ่มระยะเวลา/ราคา — “แตะเพื่อเพิ่มหรือยกเลิกรายการ”
3. คำว่า `เพิ่มแล้ว` — “รายการที่เลือกสำเร็จ”
4. แถบสรุปด้านล่าง — “ตรวจจำนวนบริการ ระยะเวลา และราคา”
5. ปุ่ม `ดำเนินการต่อ` — “ไปขั้นตอนถัดไป”

**คำเตือน**

- ยอดที่แสดงในขั้นตอนการจองเป็นราคาประเมินรวม
- หากเลือกแพ็กเกจสำหรับ 2 ท่าน ระบบจะตั้งจำนวนผู้รับบริการเป็น 2 ท่านโดยอัตโนมัติ

### หน้า 04 — ขั้นตอน 2 จาก 5: กำหนดผู้รับบริการและลำดับบริการ

**เป้าหมาย**  
ให้ลูกค้าจัดบริการของแต่ละคนได้ถูกต้อง โดยเข้าใจว่าบริการของแต่ละคนทำต่อเนื่องและผู้รับบริการทุกคนเริ่มพร้อมกัน

**ข้อความหลัก**

- หัวเรื่อง: “2. จัดบริการสำหรับแต่ละท่าน”
- เลือกจำนวนผู้รับบริการ 1 หรือ 2 ท่าน
- ตรวจลำดับบริการของแต่ละท่าน
- ใช้ปุ่มลูกศรขึ้น/ลงเพื่อเปลี่ยนลำดับ หรือ `×` เพื่อลบรายการ
- ใช้ `+ เพิ่มบริการ` เพื่อเพิ่มรายการให้ผู้รับบริการคนนั้น

**ขั้นตอนลูกค้า**

1. เลือกจำนวนผู้รับบริการ
2. ตรวจว่าผู้รับบริการทุกท่านมีอย่างน้อยหนึ่งบริการ
3. จัดลำดับบริการด้วยปุ่ม `↑` และ `↓`
4. ตรวจระยะเวลารวมของแต่ละท่าน
5. แตะ `ดำเนินการต่อ`

**ภาพที่ต้องใช้**

- `[SCREENSHOT 04A]` ตัวอย่างผู้รับบริการ 1 ท่านที่มีหลายบริการ
- `[SCREENSHOT 04B]` ตัวอย่างผู้รับบริการ 2 ท่าน โดยแสดง Treatment plan แยกกัน

**Callout**

1. ตัวเลือก `1 ท่าน / 2 ท่าน` — “กำหนดจำนวนผู้รับบริการ”
2. ลำดับหมายเลข — “บริการจะทำต่อเนื่องตามลำดับนี้”
3. ปุ่ม `↑ / ↓ / ×` — “จัดลำดับหรือลบบริการ”
4. ช่อง `+ เพิ่มบริการ` — “เพิ่มบริการได้ไม่เกิน 3 รายการต่อท่าน”
5. ระยะเวลาบนการ์ด — “ระยะเวลารวมของผู้รับบริการแต่ละท่าน”

**กรณีแพ็กเกจคู่**

- แพ็กเกจคู่จะเป็นรายการแรกของผู้รับบริการทั้งสองท่าน
- แพ็กเกจคู่คิดราคาเพียงครั้งเดียว
- บริการที่เพิ่มภายหลังคิดแยกตามผู้รับบริการแต่ละท่าน
- ระบบไม่อนุญาตให้ลดจำนวนผู้รับบริการเหลือ 1 ท่านขณะที่เลือกแพ็กเกจคู่

### หน้า 05 — ขั้นตอน 3 จาก 5: เลือกวันและเวลา

**เป้าหมาย**  
อธิบายการเลือกวันที่ ตรวจ Slot ที่ว่าง และดูเวลาสิ้นสุดโดยประมาณ

**ข้อความหลัก**

- หัวเรื่อง: “3. เลือกวันและเวลาเข้ารับบริการ”
- วันที่เลือกได้ขึ้นอยู่กับช่วงจองล่วงหน้าที่ร้านกำหนด หน้าจอจะแสดงช่วงวันที่ล่าสุดเสมอ
- ระบบจะแสดงเฉพาะเวลาที่รองรับห้องและพื้นที่บริการตามรายการที่เลือก
- เวลาทั้งหมดเป็นเวลาประเทศไทย

**ขั้นตอนลูกค้า**

1. แตะ `แตะเพื่อเปิดปฏิทิน`
2. เลือกวันที่ แล้วแตะ `ใช้วันที่นี้`
3. รอระบบตรวจสอบเวลาว่าง
4. เลือกเวลาเริ่มจาก `ช่วงเช้า`, `ช่วงบ่าย` หรือ `ช่วงเย็น`
5. ตรวจเวลาเริ่ม–สิ้นสุดของผู้รับบริการแต่ละท่าน
6. แตะ `ดำเนินการต่อ`

**ภาพที่ต้องใช้**

- `[SCREENSHOT 05A]` ปฏิทินสำหรับเลือกวันที่
- `[SCREENSHOT 05B]` รายการเวลาว่างและกล่องสรุปเวลาที่เลือก

**Callout**

1. ช่วงจองล่วงหน้า — “ตรวจช่วงวันที่ที่สามารถจองได้”
2. ปุ่ม `ใช้วันที่นี้` — “ยืนยันวันที่ก่อนดูเวลาว่าง”
3. กลุ่มเวลา — “แตะเวลาเริ่มที่ต้องการ”
4. กล่อง `เวลาที่เลือก` — “ตรวจเวลาสิ้นสุดโดยประมาณของแต่ละท่าน”

**กรณีไม่มีเวลาว่าง**

- หากเห็นข้อความ `วันนี้ไม่มีเวลาว่าง กรุณาเลือกวันอื่น` ให้เปิดปฏิทินและเลือกวันใหม่
- หากเห็นข้อความ `ตรวจสอบเวลาว่างไม่สำเร็จ` ให้แตะ `ลองอีกครั้ง`

**คำเตือน**

- ระบบจะตรวจเวลาว่างซ้ำเมื่อส่งคำขอ ช่วงเวลาที่เลือกจึงยังไม่ถูกยืนยันในขั้นตอนนี้

### หน้า 06 — ขั้นตอน 4 จาก 5: ข้อมูลผู้รับบริการและสุขภาพ

**เป้าหมาย**  
ช่วยให้ลูกค้ากรอกข้อมูลที่จำเป็นครบถ้วน พร้อมเข้าใจเหตุผลและขอบเขตความยินยอมด้านสุขภาพ

**ข้อความหลัก**

- หัวเรื่อง: “4. กรอกข้อมูลผู้รับบริการ”
- กรอก `เบอร์โทรศัพท์ผู้ติดต่อหลัก`
- กรอก `ชื่อเล่น` ของผู้รับบริการแต่ละท่าน
- เลือก `ไม่มีข้อมูลสุขภาพที่ต้องแจ้ง` หรือ `มีข้อมูลสุขภาพที่ต้องแจ้ง`
- หากมีข้อมูลสุขภาพ ให้ระบุอาการ โรคประจำตัว หรือการแพ้ที่เกี่ยวข้อง
- อ่าน “เหตุผลที่ต้องขอความยินยอม” แล้วเลือก Checkbox ความยินยอมของผู้รับบริการแต่ละท่าน

**ขั้นตอนลูกค้า**

1. กรอกเบอร์โทรศัพท์ที่ร้านติดต่อได้
2. กรอกชื่อเล่นแยกตามผู้รับบริการ
3. ตอบคำถามข้อมูลสุขภาพทุกคน
4. หากเลือกว่ามีข้อมูลสุขภาพ ให้กรอกรายละเอียดที่จำเป็นต่อความปลอดภัย
5. อ่านและให้ความยินยอมด้านข้อมูลสุขภาพ
6. สำหรับการจอง 2 ท่าน ให้ยืนยันว่าได้รับอนุญาตจากผู้รับบริการคนที่สอง
7. แตะ `ดำเนินการต่อ`

**ภาพที่ต้องใช้**

- `[SCREENSHOT 06A]` แบบฟอร์มข้อมูลผู้รับบริการ โดยใช้ข้อมูลสมมติ
- `[SCREENSHOT 06B]` สถานะเมื่อเลือก `มีข้อมูลสุขภาพที่ต้องแจ้ง` โดยปิดบังข้อความในช่องรายละเอียด
- `[SCREENSHOT 06C]` Checkbox ยืนยันสิทธิ์ของผู้รับบริการคนที่สอง

**Callout**

1. เบอร์โทรศัพท์ — “ใช้สำหรับติดต่อเกี่ยวกับการจองนี้”
2. ตัวเลือกข้อมูลสุขภาพ — “ต้องเลือกคำตอบสำหรับผู้รับบริการทุกท่าน”
3. รายละเอียดสุขภาพ — “ระบุเฉพาะข้อมูลที่จำเป็นต่อความปลอดภัยในการรับบริการ”
4. ความยินยอม — “อ่านรายละเอียดก่อนเลือก Checkbox”
5. การยืนยันแทนบุคคลที่สอง — “ต้องได้รับอนุญาตก่อนส่งข้อมูลแทน”

**Privacy**

- ข้อมูลสุขภาพเป็นข้อมูลอ่อนไหว ใช้เพื่อประเมินความเหมาะสมและเตรียมบริการอย่างปลอดภัย
- ห้ามนำข้อมูลสุขภาพจริงมาใช้ใน Screenshot, Artwork หรือไฟล์ส่งต่อ
- ลูกค้าสามารถอ่านนโยบายความเป็นส่วนตัว และติดต่อร้านเพื่อถอนความยินยอมหรือขอใช้สิทธิได้

**ขั้นตอนลูกค้า**

**Callout**

2. `ราคาประเมินรวม` — “ตรวจยอดก่อนส่งคำขอ”

**คำเตือน**

## 7. Checklist ก่อนส่ง Artwork

### ความถูกต้องของเนื้อหา

- [ ] ใช้ Booking flow 5 ขั้นตาม Customer Web ปัจจุบัน
- [ ] ชื่อปุ่มและสถานะตรงกับ Screenshot จริง
- [ ] แสดง `ราคาประเมินรวม` ระหว่างจอง ไม่เรียกว่า “ยอดชำระแล้ว”
- [ ] หน้า Request received ระบุชัดว่า `รอร้านยืนยัน`
- [ ] ไม่สื่อว่าเลือก Slot แล้วเท่ากับยืนยันการจอง
- [ ] ไม่สื่อว่ากลับจากแอปธนาคารแล้วเท่ากับชำระสำเร็จ
- [ ] การชำระเงินเริ่มจาก Booking ที่ `เสร็จสิ้น` และมีสิทธิ์ชำระ
- [ ] การแก้ไขหรือยกเลิกให้ติดต่อร้าน ไม่มี Self-service CTA ที่ไม่มีอยู่จริง
- [ ] Campaign อยู่ในภาคผนวกและไม่ถูกนำเสนอเป็นขั้นตอนบังคับของการจอง

### ความเป็นส่วนตัวและความปลอดภัย

- [ ] ไม่มีชื่อ เบอร์โทร วันเกิด ข้อมูลสุขภาพ หรือรายการชำระของลูกค้าจริง
- [ ] ไม่มี LINE User ID, ID token, Secure Status token หรือ Payment reference จริง
- [ ] QR ใน Artwork สแกนไม่ได้
- [ ] Coupon code เป็นข้อมูลตัวอย่างและมีลายน้ำ
- [ ] ไม่แสดง OTP, PIN, รหัสผ่าน หรือยอดคงเหลือธนาคาร
- [ ] Marketing consent ถูกแสดงว่า “ไม่บังคับ” อย่างชัดเจน

### คุณภาพงานออกแบบ

- [ ] อ่านง่ายที่ความกว้าง 360, 390 และ 430 px
- [ ] Callout ไม่บังปุ่ม ราคา สถานะ หรือข้อความ Error
- [ ] ไม่ใช้สีเพียงอย่างเดียวในการอธิบายสถานะ
- [ ] ตัวอักษรและ Contrast ผ่าน WCAG 2.2 AA
- [ ] ภาษาไทยไม่ถูกตัดคำผิด และไม่มีข้อความสำคัญถูก Truncate
- [ ] Forest Green, Spa Gold และ Warm Cream ถูกใช้อย่างสอดคล้องกับแบรนด์
